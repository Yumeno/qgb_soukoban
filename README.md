# qgb_soukoban

夜の倉庫を舞台にした、絵文字グリッドグラフィックの倉庫番(ソコバン)ゲームです。ブラウザだけで動きます。
収録 10 ステージ(生成 → 機械検証 → 選抜)に加えて、いつでも新しい面を作れるランダムモードがあります。

## 起動方法

このゲームは ESM (`type="module"`) を使っているため、`index.html` を直接ダブルクリックしても動きません。ローカル HTTP サーバを経由してください。

```powershell
.\serve.ps1
# または
py -3 -m http.server 8000
```

起動したらブラウザで `http://localhost:8000/` を開きます。

## 遊び方

盤面の中で自分(🧑‍🏭)を動かして、箱(📦)をすべてゴール(破線枠)まで押し込めばクリアです。箱は引くことができず、押した先に壁や別の箱があると押せません。

| キー | 動作 |
|---|---|
| ↑↓←→ / WASD | 移動 |
| Z / Backspace | undo(1手戻す) |
| R | リセット(ステージの最初からやり直す) |
| Esc | メニュー(ステージ選択)へ戻る |

画面には歩数・最短手数・自己ベストが常時表示されます。

## 査定ランク

ステージをクリアすると、歩数に応じて「特・優・良・可」の査定が下ります。最短手数(そのステージの理論最少歩数)にどれだけ迫れたかを競う遊び方です。

| 査定 | 条件 |
|---|---|
| 特 | 歩数が最短手数と一致 |
| 優 | 最短手数 + `max(2, 最短手数の10%を切り上げ)` 以内 |
| 良 | 最短手数 + `max(5, 最短手数の30%を切り上げ)` 以内 |
| 可 | それより多い歩数でクリア |

自己ベストが更新された場合はクリア直後に保存され、次回表示から反映されます。

## 模範リプレイ

各ステージには模範リプレイ(最短手数での解法)が用意されており、「模範リプレイを見る」から再生できます。

**注意**: 一度視聴すると、そのステージでは「特」を取れなくなります(視聴後に最短手数でクリアしても「優」止まりになります)。これは模範リプレイを見て手順をなぞるだけの攻略を防ぐための仕様です。視聴履歴は「記録の全消去」でのみ解除でき、「クリア記録の初期化」では解除されません。

## ランダムモード

ステージ選択画面の「ランダムモード」から、難易度(easy / normal / hard)を選んで新しい面で遊べます。面は難易度ごとに 50 件の検証済み候補(すべて解けることを機械検証済み)からランダムに出題され、未プレイの面が優先されます。一巡後や再起動後は同じ面が再出題されることがあります。

- 遊んだランダム面は「遊んだランダム面」の履歴棚に残り、そこから同じ面に再挑戦できます(保存は最大50件、棚には直近10件を表示)。
- ランダム面のクリア・自己ベスト・模範リプレイ視聴も履歴のエントリごとに保存されます(履歴棚に「BEST n」表示)。

## 記録

自己ベスト・クリア記録・模範リプレイの視聴履歴・ランダム面の履歴は、ブラウザの localStorage に保存されます(サーバには送信されません)。別のブラウザ・別の端末では記録は共有されません。

記録管理には2種類のリセットがあります。

| 操作 | 削除されるもの |
|---|---|
| クリア記録の初期化 | 収録ステージとランダム履歴内のクリア結果のみ。ランダム履歴の面自体と模範リプレイの視聴フラグは残るため、「特」の制限は解除されない |
| 記録の全消去 | クリア記録・模範リプレイの視聴履歴・ランダム履歴のすべて(確認は2段階) |

## 開発者向け

### 動作要件

- **Node.js 22 系の 22.23.4 以上**(テスト・生成ツール・品質ゲートの実行に使用。ゲーム本体の動作には不要)
  - 対応範囲は `package.json` の `engines.node` が正: `^22.23.4`(22 系のセキュリティ修正版以上。動作確認済みの系列のみを記載し、24 系以降は検証後に追加する)
  - 推奨バージョンは `.node-version`(`22.23.4`)。nvm / fnm / Volta / mise 等のバージョンマネージャで参照できる
- npm 依存はないため `npm install` は不要(ビルド工程もなし)

### コマンド

- テスト: `node --test`(引数なし。`node --test tests/` のようなディレクトリ指定はこの環境では `ERR_MODULE_NOT_FOUND` になるため使わない。組込の自動検出 `tests/**/*.test.mjs` に任せる)
- 品質ゲート: [qgb (quality-gate-builder)](https://github.com/Yumeno/Quality-gate-builder) で `.venv\Scripts\python.exe -m qgb run <REQ-ID> --yes` を実行し、証跡を `.quality-system/evidence/` に残す
- 収録ステージの再生成: `node tools/curate-stages.mjs`(生成器の候補群から難易度カーブ・多様性制約を満たすものを選抜し `src/core/stages.js` を焼き直す。手で編集しない)
- 設計文書:
  - [docs/design.md](docs/design.md) — 要件・アーキテクチャ・品質保証方針
  - [docs/ui-design.md](docs/ui-design.md) — 「夜の倉庫 × 絵文字」の世界観・配色・画面レイアウト
  - [docs/test-design.md](docs/test-design.md) — テスト方針
  - [docs/qgb-design.md](docs/qgb-design.md) — 品質ゲートの契約設計
  - [docs/difficulty-theory.md](docs/difficulty-theory.md) — 難易度スコアリングの理論
