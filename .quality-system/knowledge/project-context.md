# プロジェクトコンテキスト

このファイルは対象プロジェクトの前提情報・背景・運用方針を人間向けに記録するメモである。
qgb は本ファイルを直接機械処理しない（機械正本は `project-context.json` 側）。

## 目的

テキストアートのブラウザ倉庫番ゲームを TDD (Red→Green→Refactor) で開発し、その品質保証を
qgb (quality-gate-builder) の機械ゲートで担保する。採用判定の根拠を「見た目の良さ」や
「LLM の納得感」ではなく、再現可能な機械証跡 (gate.json) に置くことが目的。

## 対象範囲

対象:

- `src/core/` — DOM 非依存の純粋 ESM ロジック（盤面モデル・ゲーム状態機械・BFS ソルバー・
  逆押し生成器・PRNG・手作りステージデータ）。node:test の単体テスト対象。
- `src/ui/` — DOM 依存の薄い層（描画・localStorage 読み書き・画面遷移）。ロジックを持たない。
- `tests/` — node:test (`*.test.mjs`) による単体テスト。
- `tools/` — 検査スクリプト（全ステージ可解性検証など）。qgb の command 契約から呼ばれる。
- 手作り 10 ステージ（チュートリアル→高難度の難易度カーブ）+ 逆押し（pull）による
  ランダム生成モード。

対象外（out of scope）:

- ビルド工程（npm ビルドツール、バンドラ）は導入しない。
- サーバサイド機能（マルチプレイ、アカウント管理等）は範囲外。

## 既知の制約・前提

- 実装言語: vanilla JS (ES2022, ESM)。ビルド工程なし。
- 実行環境: Node.js v22.16.0（node:test 組込ランナーを使用）。ブラウザはローカル HTTP
  サーバ経由で ESM を読み込む（`file://` は CORS 制限で不可）。
- テスト: `node --test tests/` のみで完結させる。

### 採用しない方式とその理由

- **npm 依存の追加**: 依存ゼロ方針（NF-01）。ビルド工程・パッケージ管理の複雑さを持ち込まない。
- **jsdom 等のテスト専用依存**: UI 層はロジックを持たない薄い層に保ち、単体テスト対象は
  core 側に集約する。UI の検証は構文検査（`node --check` 相当）・参照整合チェック・
  目視確認で行う（jsdom 導入のコストに見合わない）。
- **CI サービス連携（GitHub Actions 等）**: 当面はローカル実行のみ。マイルストーンごとに
  git commit/push で証跡（qgb evidence 含む）を固定する運用とし、外部 CI は導入しない。
- **manual_check 段階（目視確認を qgb の判定に含めること）**: qgb は P6（LLM 単独で
  ALLOW を出してはならない）に従い、`manual_check` を含む REQ は実行を拒否する。
  見た目・操作感の確認は qgb の外（ユーザーへの動作確認依頼）で行い、機械検査のみで
  ALLOW/DENY を判定する。
