## 1. コンセプト

**「夜の倉庫 × 絵文字」**

夜間営業中の倉庫(コンクリート床、塗装ライン、ナトリウム灯、出荷伝票)の世界観をダーク基調で構築し、盤面そのものは絵文字グリッドで描く。

- レトロターミナル風(黒背景+蛍光緑)は不採用。ネオン/ハッカー感ではなく、実在の倉庫作業現場の質感(コンクリート・鋼材・ナトリウム灯のアンバー・伝票の紙色)を基調とする。
- 盤面の意味論(壁・箱・プレイヤー・ゴール)は絵文字で直感的に表現し、ゴールだけは例外的に CSS 図形(破線枠)で表現する(理由は §3 参照)。
- HUD は「出荷伝票」のメタファーで統一し、クリア演出は「出荷完了スタンプ」に一点集中する(動きは最小限、その分このスタンプ演出の質を上げる)。

## 2. パレット

6 色構成。CSS カスタムプロパティは `:root` に定義し、実装者は以下の変数名をそのまま使用する。

| 役割 | 色名 | HEX | CSS 変数名 | 用途 |
|---|---|---|---|---|
| 背景 | 床コンクリート | `#16171B` | `--color-bg` | ページ/盤面外側の背景 |
| 補助 | 鋼材グレー | `#4A5160` | `--color-steel` | 壁下地・区切り線・非アクティブ枠・補助テキスト |
| アクセント | ナトリウム灯アンバー | `#F5A623` | `--color-amber` | ゴール枠(未達成)、注目要素のアクセント |
| 成功 | 塗装グリーン | `#2FBF71` | `--color-green` | 箱 on ゴール枠、クリア済みマーク、成功系フィードバック |
| 明部 | 作業灯ホワイト | `#F2EFE6` | `--color-paper` | 本文文字色、伝票(HUD)カードの下地 |
| 警告/検印 | 検印朱 | `#E4572E` | `--color-stamp` | クリアスタンプ、警告表示 |

補足:
- 派生色(hover・disabled・shadow 等)が必要な場合は上記 6 色の alpha 調整(例: `color-mix()` または rgba)で作る。新規の色相を追加しない。
- 盤面の「床」タイルは絵文字を置かず、`--color-bg` より僅かに明るいニュートラル(例: `--color-bg` に `--color-steel` を低 alpha で重ねる)でタイル間の格子を表現する。専用変数は設けず実装時に `color-mix(in srgb, var(--color-bg) 85%, var(--color-steel) 15%)` 等で導出してよい。

## 3. 盤面マッピング

内部の盤面記法(design.md §4: `# ` `$` `@` `+` `*` `.`)は不変。描画層(`ui/render.js`)でのみ以下の見た目に変換する。

| 内部記法 | 意味 | 見た目 |
|---|---|---|
| `#` | 壁 | 🧱(絵文字) |
| ` ` | 床 | 絵文字なし。ニュートラルタイル背景のみ(§2 補足) |
| `@` | プレイヤー | 🧑‍🏭(絵文字) |
| `$` | 箱 | 📦(絵文字) |
| `.` | ゴール(空) | **絵文字を使わず CSS 破線枠**。色は `--color-amber`。理由: 🎯 等の絵文字はゴール(荷下ろし地点)の意味を直感的に伝えないため不採用(ユーザー指摘) |
| `*` | 箱 on ゴール | 📦 + セル枠が `--color-green` に点灯 + ほのかなグロー(`box-shadow` で `--color-green` を薄く外側に広げる。強さは §6 の品質フロアに従い控えめ) |
| `+` | プレイヤー on ゴール | 🧑‍🏭 + 足元に破線枠(色は `--color-amber` のまま。プレイヤーが乗っているだけでは未達成のため green にしない) |

### ゴール枠の3状態(まとめ)

| 状態 | 対応記法 | 枠の見た目 |
|---|---|---|
| 未達成(空ゴール) | `.` | 破線枠、`--color-amber`、通常の線幅・不透明度 |
| プレイヤーが乗っている(箱なし) | `+` | 破線枠、`--color-amber`(状態は変えない。箱が乗るまでは未達成) |
| 箱が乗っている(達成) | `*` | 実線寄りに変化してよいが最低限は「枠色が `--color-green` に切り替わる」+ グロー。破線→実線の変更は任意(実装簡略化のため破線のままでも可) |

### 描画方式

- 絵文字は等幅(モノスペース)でないため、テキストフローでの直接描画は不可。**固定サイズセルの CSS グリッド**(`display: grid`, `grid-template-columns: repeat(width, var(--cell-size))` 等)で盤面を構成し、各セルは固定 `width`/`height` の箱で、内部の絵文字を `display:flex; align-items:center; justify-content:center` で中央配置する。
- フォントは絵文字表示可能なシステム標準(Segoe UI Emoji / Apple Color Emoji / Noto Color Emoji 等)に委ね、Web フォント読み込みは行わない(NF-01: 依存ゼロの方針に合わせる)。CSS の `font-family` には絵文字セルにのみ `"Segoe UI Emoji", "Apple Color Emoji", "Noto Color Emoji", sans-serif` 等のフォールバックチェーンを指定してよいが、外部取得は禁止。
- セルサイズ (`--cell-size`) はビューポート幅に応じて可変にし(例: `clamp()` を使用)、盤面の最大幅・最大高さに対してセル数から逆算する。実装時に盤面の width/height を JS 側で CSS カスタムプロパティに反映する想定(詳細は Codex の実装判断に委ねる)。

## 4. タイポグラフィ

| 用途 | フォント方針 |
|---|---|
| UI 本文全般(見出し・ボタン・説明文) | システム UI サンセリフスタック: `"Segoe UI", "Yu Gothic UI", Meiryo, system-ui, sans-serif` |
| 伝票(HUD)内の数値・ラベル | 等幅: `"Consolas", "SF Mono", "Cascadia Mono", monospace`。歩数・最短手数・自己ベスト・ステージ番号などの帳票的な数値表示に限定して使用し、帳票感を出す |
| 見出し(画面タイトル・カード見出し) | 太字 (`font-weight: 700` 前後) + 字間広め(`letter-spacing: 0.05em` 程度)+ 小さい英字ラベルを添える(例: 見出し本文の上か横に `STAGE-SELECT` `WAREHOUSE-NIGHT` のような管理番号/ラベル風の小文字テキストを `--color-steel` や薄い `--color-paper` で配置) |

## 5. 画面別レイアウト

3 画面はいずれもダーク背景(`--color-bg`)を基調とする。以下は概念的な配置を示すワイヤーフレームで、実寸・ブレークポイントは実装時に調整してよい。

### 5.1 ステージ選択画面

「棚に並んだ 📦 カード」のメタファー。クリア済みカードには検印(小さな朱色スタンプ)を付す。

```
+--------------------------------------------------------------+
|  WAREHOUSE-NIGHT                                              |
|  倉庫番                                     ステージ選択       |
+--------------------------------------------------------------+
|                                                                |
|   [📦 01 ✅]  [📦 02 ✅]  [📦 03   ]  [📦 04   ]  [📦 05   ]  |
|                                                                |
|   [📦 06   ]  [📦 07   ]  [📦 08   ]  [📦 09   ]  [📦 10   ]  |
|                                                                |
|   ------------------------------------------------------      |
|   [ 🎲 ランダムモード: easy / normal / hard ]                  |
|                                                                |
+--------------------------------------------------------------+
```

- 各カードは伝票紙色(`--color-paper`)を基調にした小カード、またはダーク背景に `--color-steel` の枠を持つカード(実装時にどちらか一方に統一。伝票メタファーを強めるなら紙色ベース推奨)。
- クリア済みカードには検印朱(`--color-stamp`)の小さなチェック/スタンプ意匠 + 自己ベスト歩数を添える。
- 未クリアカードは `--color-steel` 寄りの控えめな見た目(視線誘導しない)。

### 5.2 ゲーム画面

- 狭い画面(モバイル幅)では伝票 HUD が盤面の下に落ちる縦積みレイアウトに切り替える(§6 品質フロア)。
- 伝票カードは `--color-paper` の明るいカード。ダーク背景上に浮かせ、軽い `box-shadow` で「紙が置かれている」質感を出す。
- 伝票内のラベル(`STAGE` `MOVES` `MIN` `BEST` 等)と数値は等幅フォント(§4)。ラベルは英字+コロンの帳票的な書式に揃える。

### 5.3 クリアオーバーレイ

伝票に「出荷完了」の朱色ハンコが斜めに押される演出(§6 で詳述)。

```
        +----------------------------------+
        |   出荷伝票                        |
        |   ------------------------------  |
        |   STAGE   : 03                    |
        |   MOVES   : 27        [ 出荷完了 ] |  <- スタンプは斜め・半透明開始→定位置
        |   MIN     : 19          (朱色)     |
        |   BEST    : 21 -> 21              |
        |   ------------------------------  |
        |                                    |
        |   [ ▶ リプレイ再生 ]                |
        |   [ 次のステージへ ]  [ メニューへ ] |
        +----------------------------------+
```

- オーバーレイは背景を半透明の暗いスクリム(`--color-bg` の高 alpha)で覆い、伝票カードを画面中央に配置する。
- スタンプはカードの右上〜中央寄りに、伝票の印字を軽く隠すくらいの重なりで配置してよい(実際の検品スタンプらしさ)。

### 5.3.1 査定印(査定ランク機能。テストプレイ第4回フィードバック対応、2026-07-11/12 追加)

ユーザー要望「最短手に近いほど点が高い仕組み」への対応。クリア時の歩数を最短手数 (`minMoves`) と比較し、特(S)/優(A)/良(B)/可(C) の4段階で判定する(判定ロジックは `src/core/rank.js` の `computeRank`。design.md §8 F-09 参照)。ランダム生成面にも同一ロジックを適用する。

**査定印(クリアオーバーレイ)**:

- クリアオーバーレイに「出荷完了」スタンプ(§6)と並び、査定ランクを表す**丸印スタンプ**(`.rank-stamp`)を表示する。意匠は出荷完了スタンプと同系(斜め回転・`border: 3px solid currentColor` の円形バッジに等級ラベル1文字を配置)だが、色は下記の等級別配色で出荷完了スタンプ(`--color-stamp`固定)とは独立に変える。
- 等級ラベルはラベル欄(§1 の `RANKS`)の日本語1文字をそのまま表示: 特 / 優 / 良 / 可。
- **次目標行**: 査定印の下(または伝票内の該当行)に「あと N 手で [上位等級]」を 1 行追加する(`nextRankText`、`src/ui/app.js`)。S 判定(最短ぴったり)のときは次目標がない(`nextGrade: null`)ため、この行は表示しない(または「これ以上の等級はありません」等の到達済み表現に切り替える。空行にはしない)。

**等級別配色(§2 パレットの再利用。新規色相を追加しない)**:

| 等級 | ラベル | CSS 変数名 | 使用色 | 意図 |
|---|---|---|---|---|
| S | 特 | `.rank-s { --rank-color: var(--color-stamp) }` | 検印朱 `#E4572E` | 最上位。出荷完了スタンプと同系色で「完璧」を強調 |
| A | 優 | `.rank-a { --rank-color: var(--color-amber) }` | ナトリウム灯アンバー `#F5A623` | 僅差の惜しさを暖色でやや控えめに |
| B | 良 | `.rank-b { --rank-color: var(--color-green) }` | 塗装グリーン `#2FBF71` | クリアの成功感は保つが最上位ほど目立たせない |
| C | 可 | `.rank-c { --rank-color: var(--color-steel) }` | 鋼材グレー `#4A5160` | クリア自体は成立するが最も控えめな配色 |

**棚カードの自己ベスト査定バッジ(ステージ選択画面。§5.1 の拡張)**:

- クリア済みカード(§5.1 の検印朱チェック)に加え、自己ベスト (`bestMoves`) から `computeRank` で算出した等級バッジ(`.rank-badge`)を小さく添える。バッジの配色は上表と同一の等級別配色を使う(査定印と同じ CSS カスタムプロパティ `--rank-color` を共有し、`.rank-badge`/`.rank-stamp` それぞれの意匠差分(位置・回転・サイズ)だけを変える)。
- 未クリアカードにはバッジを表示しない(自己ベストが存在しないため)。

## 6. シグネチャ演出: 出荷完了スタンプ

移動アニメーションは実装しない(キー応答のキビキビ感を優先。design.md 通り)。装飾ホバー等の動きも最小限に留め、演出の予算はこのスタンプ 1 箇所に集中させる。

### クリアオーバーレイの表示遅延(テストプレイフィードバック対応、2026-07-11 追加)

ユーザー評価「クリアダイアログが早すぎる」への対応。勝利判定確定の直後にオーバーレイを即時表示せず、**約 700ms(`CLEAR_OVERLAY_DELAY_MS`、`src/ui/app.js`)盤面をそのまま見せてから**オーバーレイ(§5.3・本節のスタンプ演出)を表示する。

- 実装: 勝利確定時に `window.setTimeout` でオーバーレイ表示をスケジュールし、遅延中は `clearOverlayVisible=false` のまま盤面のみ再描画する。タイマー発火時点で画面がまだゲーム画面で、かつリプレイ再生中でないことを確認してから `clearOverlayVisible=true` にする(画面遷移・リプレイ再生と競合した場合はオーバーレイを出さない)。
- **遅延中も R(リセット)/Esc(メニューへ)は即時有効**(`cancelClearOverlayDelay` でタイマーを破棄してから通常の画面遷移を行う)。遅延はオーバーレイの表示だけを遅らせるものであり、操作をブロックする待機時間ではない。
- 狙い: 「箱が最後のゴールに収まった瞬間」を視覚的に確認する時間を確保し、即座にダイアログへ遷移して結果表示に埋もれる体感を避ける。

### アニメーション仕様

- 対象要素: クリアオーバーレイ内の「出荷完了」スタンプ(朱色 `--color-stamp`、斜め回転した角判・検印風の図形/テキスト)。
- 発火タイミング: クリアオーバーレイの表示と同時(上記 700ms 遅延後、オーバーレイが実際に表示されたタイミング。勝利判定確定の直後ではない)。
- 時間: 約 200ms。
- 変化: `opacity: 0 → 1`, `transform: scale(1.4) rotate(-18deg) → scale(1) rotate(-12deg)`(縮小しながら定位置に収まる「ガチャッ」と押す感触)。最終的な静止回転角は `-8deg` 〜 `-15deg` 程度の範囲で実装者が調整してよい(斜めに押されたハンコらしさが出ればよい)。
- イージング: `cubic-bezier(0.34, 1.56, 0.64, 1)` 系のオーバーシュートを伴うイージング(スタンプが少し弾んでから止まる感触)、または同等の ease-out-back 相当。厳密な係数は実装者調整可。
- 補助演出(任意): スタンプ着地の瞬間に伝票カード全体へごく短い(100ms 未満)の微小な揺れ・明滅を加えてもよいが必須ではない。過剰にしない。

### prefers-reduced-motion 分岐

- `prefers-reduced-motion: reduce` が有効な環境では、上記の scale+rotate トランジションを行わず、**スタンプを最終状態(最終 scale/rotate/opacity: 1)で即時表示**する。
- 実装は CSS の `@media (prefers-reduced-motion: reduce)` でアニメーション用のトランジション/アニメーション定義を無効化し、最終状態のスタイルのみを適用する形を基本とする(JS 側で分岐する場合も同じ最終状態に揃える)。

## 7. 品質フロア

以下は視覚実装が必ず満たすべき最低条件(design.md の非機能要件と同格に扱う)。

- **レスポンシブ**: モバイル幅(目安 375px 程度)まで崩れずに操作可能。ゲーム画面は狭い画面で伝票 HUD が盤面の下に落ちる縦積みに切り替わる(§5.2)。盤面セルサイズはビューポートに応じて縮小し、横スクロールを発生させない。
- **キーボードフォーカス可視**: ボタン・カード等のフォーカス可能要素は `:focus-visible` で明確な枠(`--color-amber` 推奨)を表示する。フォーカスを非表示にする実装(`outline: none` のみで代替なし)は禁止。
- **prefers-reduced-motion 尊重**: §6 のスタンプ演出に加え、将来動きを追加する場合も同メディアクエリで簡略化/無効化できる構成にする。
- **絵文字フォールバック**: 絵文字が正しく表示されない環境(フォント欠如等)を過度に心配して代替テキストを重ねる必要はないが、セルの固定サイズ・中央配置は絵文字グリフの縦横比に依存しないレイアウトにする(絵文字の実測サイズがフォントにより多少ずれても崩れないようにする)。
