# テスト設計書 (qgb_soukoban)

- 版: v0.3.2 (テスト実態との同期。設計表に載っていなかった超過テストを枝番 ID で追補。ユーザー指示 2026-07-11 「qgb でチェック対象としないテスト項目があってもよいが、TDD なら設計表に載せたほうが確実」による)
- 関連: [design.md](design.md) / [qgb-design.md](qgb-design.md)

## 1. TDD 運用ルール

1. **Red → Green → Refactor** を機能単位で回す。テストを先に書き、失敗を確認してから実装する。
2. テストランナーは `node --test`(引数なしの自動検出。Node 22 組込)。**npm 依存・テスト専用ランタイム依存を追加しない**。本環境では `node --test tests/` のディレクトリ指定が ERR_MODULE_NOT_FOUND になるため使わない。
3. コアロジック (`src/core/`) がテスト対象。UI (`src/ui/`) はロジックを持たない薄い層とし、単体テストしない(§6)。
4. テストはすべて決定論とする。乱数はシード固定、時刻依存を持ち込まない。
5. 実装サブエージェントへの委任単位 = テストファイル単位(受け入れ条件は本書のケース表)。

## 2. テストファイル構成

```
tests/
  board.test.mjs      # 盤面パース/検証
  game.test.mjs       # 移動・押し・undo・勝利・歩数・リプレイログ
  solver.test.mjs     # 可解性・最短歩数・デッドロック・資源上限
  generator.test.mjs  # 生成器の構成的可解性・決定論
  stages.test.mjs     # 収録10ステージ(生成選抜)の可解性・焼き込み値照合・難易度カーブ
  quality.test.mjs    # 選抜時の品質チェック(決定論・冗長箱移動検出・選抜制約)の単体テスト
  replay.test.mjs     # リプレイ適用・保存形式
```

## 3. ケース一覧

**S2 ゲートは `node --test` で実スイート全件を実行するため、本表に載る全テストが機械検査対象である。** qgb でチェック対象としない(表に載せない)テスト項目があってもよいが、TDD の観点からは設計表に載せたほうが確実である(ユーザー決定 2026-07-11)。§3.1〜3.3・3.6(board/game/solver/replay/progress、実装済み・実在するテストファイル)は `tests/*.test.mjs` の実テストを 1 件残らず追補済み。§3.4/3.5/3.7(generator/stages/quality)は 2026-07-11 現在まだ実装されていない(生成器・ステージ選抜・品質チェック機能が未着手のため対応するテストファイルが存在しない)ため、本書の先行設計のみを記載している。

### 3.2 game.test.mjs

| # | ケース | 期待 |
|---|---|---|
| G-01 | 床への移動 | 位置更新、moves +1、ログに 1 文字追加 |

| G-09 | リセット | 初期状態に完全復帰、ログ空 |

| G-14 | `applyMoves` に不正文字を含む文字列を渡す | 適用前に TypeError を投げ、状態(player/moves)も変化しない |
| G-15 | `applyMoves` に正常な文字列を渡す | 文字列の手順を順に適用し、won/moves/log が最終手順どおりになる |

| # | ケース | 期待 |
|---|---|---|
| S-01 | 手計算で最短歩数が既知の極小面(1 箱、数マス)3 種 | solvable=true、minMoves が手計算値と一致 |
| S-02 | 解なし面(箱が凹角に固定) | solvable=false |

| S-06 | 2 箱の既知面 | minMoves 一致(8 手) |
| S-06b | 4 箱・内壁を含む決定的なやや重い盤面 | 既定の展開上限内で solvable=true、solution が Game.applyMoves で勝利に到達 |
| S-07 | 状態キー関数: 箱集合の列挙順を入れ替えても同一キー | 一致(visited 正規化の直接検証) |
| S-07b | `isStaticCorner`: 左右端の列で行をまたがず盤外を壁相当として扱う | 端列(index 0)は corner 判定 true、行をまたいだ隣接マス(index 4)は誤って corner 判定しない(false) |
| S-08 | 遷移同値性プロパティテスト: シード固定のランダム盤面群で、ソルバー内部が展開する合法遷移の集合と、game.js の move を上下左右 4 方向試した結果の集合を照合 | 完全一致(違法手を許容していないこと・合法手を見落としていないことの両方を検出) |
| S-08 の決定的ケース | 箱 2 連続で押せない/箱を壁へ押せない/盤端での移動/ゴール上の箱を押す/箱 5 個と内壁のある盤面、の 5 パターンを固定盤面で先行検証 | 各パターンで legalMoves の遷移集合と Game.move の遷移集合が一致(ランダム 120 ケースの前段として決定的な代表ケースを個別に固定) |

### 3.4 generator.test.mjs

| # | ケース | 期待 |
|---|---|---|
| N-01 | 固定シード 20 個 × 難易度 3 種 | 全 60 面が validate() 合格かつソルバーで solvable=true |
| N-02 | 同一シード・同一パラメータで 2 回生成 | 完全一致(決定論) |
| N-03 | 異なるシード | 少なくとも 1 面は異なる(縮退検知) |
| N-04 | 各難易度の minMoves 下限 | easy < normal < hard の下限パラメータを満たす |

### 3.5 stages.test.mjs

前提(2026-07-11 変更): 収録 10 ステージは、逆押し生成器の候補群から design.md §7.1 の選抜手順(品質チェック通過 + 難易度カーブ整列)を経て `stages.js` に焼き込まれたものである。焼き込み後の検証対象・検証内容(T-01〜T-06 自体)はこの変更による影響を受けず、変更前と完全に同一のケースを維持する。

| # | ケース | 期待 |
|---|---|---|
| T-01 | 全 10 面が validate() 合格 | 合格 |
| T-02 | 全 10 面がソルバーで solvable=true | 合格 |
| T-03 | 焼き込み `minMoves` == ソルバー再計算値 | 全面一致(手書き値の混入防止) |
| T-04 | 難易度カーブ: minMoves がステージ番号に対し概ね単調増加 | stage1 が最小、stage10 が最大。隣接の逆転は 1 箇所まで許容 |

### 3.6 replay.test.mjs / progress.test.mjs

R-01〜R-03 は `tests/replay.test.mjs` に実装。R-04/R-05 は `src/core/progress.js` の純粋直列化ロジックを対象とし、`tests/progress.test.mjs` に実装(ファイル分離。§末尾の注を参照)。

| # | ケース | 期待 |
|---|---|---|
| R-01 | クリアまでの操作列のログをリセット後に適用 | 勝利状態に到達、moves 一致 |
| R-02 | undo を挟んだプレイのログ | undo 後の実効手順のみが残り、適用で同一終局 |
| R-03 | 不正文字を含むリプレイ文字列の適用 | 明示エラー(黙って無視しない) |
| R-04 | progress.js のスキーマ往復 (serialize → deserialize) | bestMoves/replay/clearedAt が保存される。壊れた JSON・版不一致は初期状態を返す |
| R-04b | 壊れた JSON / version 不一致 / null や非オブジェクトの JSON を deserialize | いずれも初期状態(`{version:1, stages:{}}`)を返す(throw しない。R-04 の異常系境界) |
| R-05 | progress.js の記録マージ (merge) | bestMoves は**改善時のみ**更新、replay は bestMoves 更新時に同時更新 |
| R-05b | 未クリアのステージへの初回記録 | 新規作成され cleared:true が立つ(bestMoves/replay/clearedAt がそのまま反映) |
| R-05c | 悪化時(moves が既存 bestMoves より大きい) | 既存の bestMoves/replay/clearedAt/cleared を維持(更新しない) |
| R-05d | 同値時(moves == 既存 bestMoves) | 既存の replay/clearedAt を維持(改善時のみ更新という規則の境界値確認) |
| R-05e | mergeClearRecord の immutability | 元の progress オブジェクトを変更しない(戻り値は新規オブジェクト) |
| R-05f | 別ステージへの記録マージ | 既存ステージ(stage1)の記録に影響を与えない(ステージ間の独立性) |

注: 純粋直列化ロジックは `src/core/progress.js` に置き node:test でテストする。`src/ui/storage.js` は localStorage adapter に限定しロジックを持たない(Codex 指摘: 配置とテスト対象の整合)。

### 3.7 quality.test.mjs

収録ステージの選抜(design.md §7.1)に関わる検査の単体テスト。候補の品質チェックは 2 点のみ(Q-01/Q-02 が対象とする決定論と冗長判定。複雑な面白さスコアリングは導入しない)。Q-03 は品質チェックではなく、**焼き込み後の選抜結果が満たすべき不変条件**(10 面・難易度単調・規模上限・ID 一意)の検査であり、両者を区別する。

| # | ケース | 期待 |
|---|---|---|
| Q-01 | 品質チェックの決定論: 同一入力(同一盤面 + 同一ソルバー解)を複数回チェック | 同一判定(通過/棄却)を返す |
| Q-02 | 冗長箱移動検出の正しさ: ソルバーが返す代表最短解 1 本を、初期箱位置で付与した箱 ID を保持したまま replay し、push された箱 ID ごとに占有マスの履歴を記録する。いずれかの箱が過去に占有したマスへ再び戻る push が 1 回でもあれば冗長と判定する | 冗長な箱移動を含む既知の面で検出(棄却対象)、含まない既知の面で非検出(通過) |
| Q-03 | 選抜結果の不変条件の遵守: 収録 10 ステージ(stages.js)に対する検査 | 10 面ちょうど・難易度(minMoves)が単調(T-04 と同一基準)・規模上限(箱 ≤ 5、盤面 ≤ 12×10)を全面満たす・ステージ ID 重複なし |

## 4. 性能条件

- 収録 10 面すべて: ソルバーが 1 面あたり **5 秒以内**(CI 相当環境)で解を返す(stages.test.mjs でタイムボックス)。
- 超過時はテスト失敗 = ステージ選抜をやり直す(ソルバーの上限緩和で逃げない)。

## 5. 受け入れの定義 (実装サブエージェント向け)

- 担当テストファイルの全ケース Green + 既存テストにリグレッションなし
- `node --test`(引数なし自動検出)がゼロ exit
- 新規ランタイム依存の追加なし(import は Node 組込 + 自プロジェクトのみ)

## 6. UI 層の検証方針

- UI にはロジックを書かない(依存方向 ui→core の一方向を守る)ことで単体テスト対象を core に集約する。
- UI の機械検証は qgb ゲートで行う: ESM 構文検査 (`node --check`)、参照整合(index.html が参照するファイルの存在)。
- 操作感・見た目は目視確認(ユーザー実施)。**目視は qgb の ALLOW 根拠にしない**(P6。qgb-design.md 参照)。
