- 状態: v0.2(Fable 5 起草 v0.1 → Codex 高推論モデル gpt-5.6-sol のレビュー + Sonnet の文献調査を統合した改訂。
  中心命題〔push 空間への商写像〕は強い同意を得て確定、Φ の定義・生成側アイデアの2点は不成立と判明したため撤回・置換した)
- 位置づけ: 設計判断の下敷きとなる理論検討。採用された結論のみが design.md に反映される
- 発端: テストプレイ第2回の指摘 — 「最短歩数(minMoves)が大きい=難しい、は成り立たない。歩き回るだけで稼げてしまい、荷物がほとんど動かない面が最難と判定された(stage10)」

## 1. 問題の定式化: なぜ歩数は難易度にならないか

倉庫番の状態は (箱配置 b, プレイヤー位置 p) の組だが、プレイヤーの**歩行は自由運動**である:
可逆・低コスト・プレイヤーは歩行の計画をほぼ意識しない(押したい位置まで歩くだけ)。
一方**押し(push)は操作**である: 不可逆になり得て、盤面の将来を拘束する。

したがって認知的な難しさが宿るのは**押しの計画**にあり、歩数はその間を埋める「移動時間」にすぎない。
minMoves を難易度に使うと「広い盤面で 1 箱を遠くまで運ぶだけの面」が最難になる — これが観測された病理。

文献調査(§1.1)もこの直感を裏付ける: 最短経路長(手数)と人間の解答時間の相関は弱く、
箱の動きに着目した指標の方が有意に強い相関を示す。

### push 空間への商写像(中心命題・確定)

標準的な定式化: プレイヤー位置は「フリースペースの連結成分」までしか意味を持たない。
状態を **(箱配置 b, プレイヤーの可達成分 r)** に商して、遷移を「push 1 回」とするグラフ(push 空間)を考える。

- 歩行は同一ノード内の自由運動として消える
- 解 = push 空間上の経路。**難易度は push 空間のグラフ構造の性質**として定義すべき
- 副産物: push 空間で探索するソルバー(push-optimal BFS)は状態数が激減し、現行 BFS の資源上限問題(hard 生成の妥協)も同時に解消する

**レビュー修正 (a): どの解の上で指標を測るか。**
指標は「生成時に得られた証明用の解(逆押し生成の副産物)」ではなく、
**push 空間の最適解のうち、辞書式順序で (minPushes を最小化 → その中で minMoves を最小化) を満たす代表解**
の上で測る。理由: 同じ minPushes を達成する解は複数あり得て、そのうち歩行距離が最小のものが
「プレイヤーが実際に選ぶであろう解」に最も近い代表点になる。生成証明解は途中の探索順序に依存し、
代表性を持たない。

### 1.1 文献との相関: 手数系指標は弱い、箱の動き系指標は強い

Jarušek & Pelánek (STAIRS 2010) が人間の解答時間と各指標の相関を実測している。要旨:

| 指標 | 相関(人間解答時間との相関係数) | 出典 |
|---|---|---|
| 最短経路長(手数, moves) | Pearson 0.30 / Spearman 0.47(弱い) | Jarušek & Pelánek 2010 |
| 状態空間サイズ | -0.11(ほぼ無相関、符号も直感に反する) | Jarušek & Pelánek 2010 |
| box changes(箱の切替回数) | 0.74(強い) | Jarušek & Pelánek 2010 |
| 2-decomposition(解の分割可能性) | 0.82(最強) | Jarušek & Pelánek 2010 |
| counterintuitive moves(直感に反する手) | 0.69(強い) | Jarušek & Pelánek 2010 |
| 人間探索の計算シミュレーション | Pearson 0.76 | Jarušek & Pelánek 2010 |
| A* closed list サイズ(探索コスト) | 高相関(人間の苦労と一致) | Kartal et al., AIIDE |

結論: **手数(moves/pushes 単体)は難易度指標としての実証的な支持が薄い**。

## 2. ポテンシャル法の視点: 「直感に逆らう手」の計量

ロボット工学のポテンシャル法は、ゴールへの引力 + 障害物の斥力の勾配降下で経路を作る。
その最大の弱点は**ローカルミニマム**に捕まること — そして人間プレイヤーの直感的な解き方(「箱をゴールへ近づける」)は、まさにこの勾配降下に相当する。

**仮説(維持): 人間が詰まる場所 = 自然ポテンシャルのローカルミニマム。難しさの第一成分は「ポテンシャルに逆らう必要量」である。**

### Φ の定義(レビュー修正 (b) により再定義)

v0.1 では Φ(b) を「箱とゴールの最小コストマッチング(押し経路距離ベース)」とし、
指標は「uphill push の数」としていた。レビューで以下の問題が指摘され、修正した。

- **修正前の問題**: uphill push の単純カウントは、Φ が同値のまま横滑りする push(プラトー)や、
  小さな後退の繰り返しと 1 回の大きな後退を区別できず、「どれだけ深い井戸から脱出したか」を捉えられない。
- **修正後の定義**:
  - Φ(b) = 箱とゴールの**reverse-pull distance(逆再生 pull で到達可能な距離)の最小マッチング**の値
    (押し経路距離ベースの割当問題という枠組みは維持しつつ、距離の定義を「その箱がゴールから pull で
    到達し得る経路長」に統一し、生成器の逆押しモデルと整合させる)
  - 指標は uphill push 数ではなく、代表解(§1 の辞書式最適解)上で以下を測る:
    1. **非下降 push 数**(Φ を減少させない push の数。プラトーを含む=停滞も難度に数える)
    2. **累積上昇量**(Φ が増加する区間の増加量の総和。小さな後退の繰り返しと1回の大きな後退を区別できる)
    3. **最大 Φ 障壁(plateau 込み)**(解経路上で「今より Φ が下がったことがない最長区間の Φ 増加量」
       = 最も深い井戸から脱出するのに必要な最大コスト。単純な合計ではなく最大値を取ることで、
       「一度は大きく後退させる必要があった」局面を検出する)

これはユーザーの言う「干渉しまくる他の荷物を壮大に動かしまくって、最後に 1 個を触る」を直接捉える:
他の箱を(ゴールに向かわない方向へ)動かす工程は Φ を下げないため、非下降 push として計上され、
その区間の Φ 増加量が最大 Φ 障壁に反映される。

## 3. 経路計画の視点: 通路の細さ・罠の密度・依存構造

### 3.1 解経路のボトルネック性(通路幅)

C 空間の細い通路を通す経路計画は難しい。倉庫番では:

- 各解経路状態での「デッドロックに至らない合法 push」の分岐数
- そのうち「最短解に留まる」push の比率(1 に近いほど一本道 = 発見が難しい / 逆に分岐過多は探索空間の広さ)

→ この観点は「deceptive branching(見せかけの分岐)」として §6 で改めて評価し、
D4 候補(見送り)として扱う(理由は §6 参照)。

### 3.2 罠(デッドロック)密度

障害物すれすれを通る経路ほど制御が難しいのと同型で、
**解経路の近傍でデッドロックに落ちる push の比率**は「うっかり死ぬ度」を測る。
simple deadlock(凹角)+ freeze deadlock(箱同士の固着)の近似検出で機械計測可能。

**指標裁定**: 罠密度は「解を見つける難しさ」ではなく「失敗しやすさ(緊張感)」という**別軸**の指標として扱う。
主軸の難易度スコアには混ぜず、診断ログの別カテゴリとして残す。

### 3.3 箱の依存グラフ(干渉構造)

「箱 A を押すための通路・押し位置を箱 B が塞ぐ」関係を有向グラフにすると、
難しい面は深い依存鎖や相互依存(一時退避)を持つ。
厳密な構築は高価だが、**最適解の push 系列から近似できる**:

- **box changes / box switch 回数**(既存実装): A→B と押す箱が切り替わる回数。
  文献(Jarušek & Pelánek 2010)で相関 0.74 と実証済みの指標であり、主軸に採用する。
- v0.1 で提案した「切替のネスト深度(A..B..A のように戻ってくる構造の深さ)」は、
  **指標裁定により具体イベントへ置換**した: 「ゴール載せ直し回数」(一度ゴールに置いた箱を再度押し出す回数)・
  「割当変更回数」(Φ のマッチングにおいて、ある箱が担当するゴールが解の途中で変わる回数)。
  抽象的な深さのスコアより、実際に観測可能な離散イベントとして定義した方が実装・解釈ともに扱いやすいため。

## 4. 機械化可能な指標セット(v0.2 裁定)

指標ごとに「主軸(難易度スコアの構成要素)/ ペナルティ(棄却・減点用)/ 診断(ログ記録のみ・スコア不使用)/ 不採用」を裁定した。

| ID | 指標 | 捉えるもの | 裁定 | 根拠 |
|---|---|---|---|---|
| M1 | minPushes(push 空間の代表解の押し数、辞書式で minMoves も併記) | 操作量の真の下限 | **主軸** | push 空間ソルバー(D1)で正確化。規模の一次近似として必要 |
| M2 | box changes(box switches。既存実装の box switch と同義) | 箱間の干渉・切替の多さ | **主軸** | Jarušek & Pelánek 2010 相関 0.74。実証的に最も裏付けが強い実装容易な指標 |
| M2' | 最大 Φ 障壁(non-decreasing push 数・累積上昇量を内訳として保持) | ポテンシャルに逆らう必要量・脱出コスト | **主軸** | §2 の修正後定義。uphill 単純カウントの欠陥(プラトー無視)を修正済み |
| M3 | ゴール載せ直し回数・割当変更回数 | 干渉構造の具体イベント(旧: ネスト深度) | **診断→校正後に主軸候補** | ネスト深度の抽象スコアを具体イベントに置換。まず診断ログで分布を見て、有効なら D4 で主軸へ格上げ |
| M4(旧) | uphill pushes 単純カウント | (旧)直感に逆らう量 | **不成立と判明した仮説として撤回**(M2' に置換) | §2 参照。プラトー・後退の大小を区別できない欠陥 |
| M5 | 罠密度(解経路近傍のデッドロック率) | うっかり詰む危険 | **診断(別軸)** | 「解く難しさ」ではなく「失敗しやすさ」の指標。主軸に混ぜない |
| M6 | push 空間の探索コスト(expanded ノード数) | 機械の苦労 ≒ 探索の広さ | **診断** | Kartal et al. は探索コストの有効性を示すが、生スケールは盤面規模に強く依存し正規化が未確立のため主軸には採らず診断ログに留める |
| M7 | moves/pushes 比 | 歩行水増しの検出 | **ペナルティ**(棄却ではなく減点) | v0.1 では棄却規則としたが、指標裁定で「一律棄却は過剰、比が高い面すべてを弾くと正当な広い盤面まで落とす」ため、スコアへの減点項に格下げ。閾値超えのみ警告ログに出す |
| M8 | box lines(同一箱・同一方向の連続 push を1と数える) | 方向転換の多さ | **診断へ降格** | v0.1 で実装候補としていたが、Taylor & Parberry では採用例があるものの Jarušek & Pelánek の直接相関データがなく、box changes(M2)と情報が重複する可能性が高い。まず診断ログで M2 との相関を確認する |
| M9 | 2-decomposition(解の並列分割可能性) | 解を独立な部分問題に分解できる余地の少なさ | **診断(D2)→校正で有効なら D4 でDAG版へ格上げ** | 文献最強の相関 0.82 だが忠実な実装(最短解DAGの保持)はソルバーのメモリ・実装面積を増やす。まず代表解1本上の軽量版(15分割×1列走査)で診断し、+0.08の限界効用が校正で確認できたら格上げ |
| M10 | 生 expanded(探索ノード数そのもの、正規化なし) | — | **不採用** | M6 と重複し、正規化なしでは盤面規模に依存しすぎてスコアに使えない |
| deceptive branching | 経路外分岐の探索コスト | 「一本道か分岐過多か」の人間的判断 | **見送り(D4候補)** | §6 参照。経路外探索の乗算的コストと、定義自体の研究的余地が残る |

## 5. 選抜への適用案(v0.2)

1. **ペナルティ規則への格下げ**: v0.1 の「moves/pushes 比 > k で棄却」は、指標裁定により**一律棄却をやめ、
   スコアへの減点項(M7)に変更**する。歩行水増し面(stage10 病理)は M1(push 基準の規模)+ M2/M2' が
   ほぼゼロに近い値を返すため、主軸スコアだけで自然に下位に落ちる。M7 は「念のため」の追加ガードとして
   ログに警告を出すのみで、正常な広い盤面を誤って弾かない
2. **難易度スコアの置換**: minMoves 単独 → 推奨最小セット **minPushes(M1)+ box changes(M2)+ 最大Φ障壁(M2')**
   の3本を主軸とし、M7(moves/pushes)は減点ペナルティとして加える。重みはテストプレイで校正する(D3)
3. **カーブの再定義**: 収録 10 面はこの合成スコアで単調に整列(minMoves は表示用に残す。§1 の代表解の
   minMoves を用いる)
4. **push 空間ソルバーの導入(D1)**: 現行 move-BFS は最短歩数の表示用に残し、
   判定・選抜は push 空間の代表解(辞書式 minPushes→minMoves)で行う二本立て

## 6. 論点の整理(v0.1 の未解決論点を解決済み/校正待ち/見送りに分類)

### 解決済み(レビューで裁定)

- Φ の定義: 押し経路距離ベースの割当問題という枠組みは維持し、reverse-pull distance に統一して
  生成器の逆押しモデルと整合させた(§2)。他箱の干渉を無視する近似である点は残るが、
  最大 Φ 障壁という「最悪区間」の取り方で単純平均よりは近似誤差の影響を抑えている
- 「分岐の少なさ=一本道 / 分岐の多さ=探索空間大」のどちらが人間に難しいか: 文献(Kartal et al. の
  A* 探索コストの高相関、Jarušek & Pelánek の counterintuitive moves 0.69)は「探索空間の広さそのもの」
  ではなく「直感に反する手が必要」「箱の切替が多い」という**構造的**な難しさが効くことを示す。
  分岐数の生カウントは代理指標として弱く、M6(診断)に留める判断で決着
- 罠密度 M5 は人間の体感難易度(緊張感)と「解を見つける難しさ」の別軸である: **指標裁定で解決**。
  診断カテゴリとして分離し、主軸スコアには混ぜない

### 不成立と判明した仮説(撤回。記録として残す)

- **v0.1 §4 M4「uphill push の単純カウント」**: プラトーや後退の大小を区別できず、Φ の質的な情報を
  捨ててしまう。M2'(最大Φ障壁・非下降push数・累積上昇量)に置換
- **v0.1 §6 末尾「生成側(逆押し)への組み込み: 逆再生中に Φ を意図的に上げる pull を優先すれば
  forward で uphill を強制できる」**: レビューで**向きが逆で不成立と判明**。逆再生(pull)で Φ を
  上げる操作は、時間反転すると forward の push では Φ を**下げる**方向に対応する
  (pull は push の厳密な逆写像であり、Φ の変化方向も反転する)。したがって「pull で Φ を上げる」
  生成方針は forward 解を平坦化・易化させる方向に働き、意図と反対の効果を生む。
  正しい対応は「生成方策の混合(複数の pull 優先度を確率的に混ぜる)+ 統一 forward 評価器
  (生成後に forward 解を代表解ソルバーで再計算し M1/M2/M2' を測る)」であり、
  生成時のヒューリスティックだけで難易度を直接誘導することはできない(D4 候補として記録)

### 校正待ち(D2 診断ログ→D3 テストプレイ校正で判断)

- M3(ゴール載せ直し回数・割当変更回数)が主軸に格上げする価値があるか
- M8(box lines)が M2(box changes)と情報重複するか、独立した診断価値があるか
- M9(軽量2-decomposition)が代表解の代替(忠実DAG版)なしでも十分な信号を持つか。
  文献の +0.08 の限界効用(box changes 0.74 → 2-decomposition 0.82)が実装コストに見合うかの判断材料にする
- M7(moves/pushes ペナルティ)の閾値 k と減点の重み

### 見送り(D4 候補。今回のスコープ外)

- **deceptive branching**(経路外分岐の探索コスト): 経路外探索のコストが乗算的に増え、
  かつ「見せかけの分岐」の定義自体に研究的な詰めの余地が残るため、D1〜D3 では扱わない
- **DAG 版 2-decomposition**(忠実な最短解DAG保持): ソルバーのメモリ・実装面積が増えるため、
  軽量版(M9)の診断結果を見てから判断する
- **生成方策の混合**: 上記「不成立と判明した仮説」の代替として提案されたアイデア。
  生成そのものを難易度誘導する仕組みであり、D1〜D3(判定・選抜側の指標整備)とは独立に
  後続フェーズで検討する

## 7. 承認済み実装計画(D1〜D3)と D4 候補

ユーザー承認済み(2026-07-11)の実装順序:

- **D1: push 空間ソルバー**
  canonical key(箱配置+プレイヤー可達成分)によるグラフ探索、静的 dead square の事前除外、
  辞書式代表解(minPushes を最小化 → その中で minMoves を最小化)の算出。
