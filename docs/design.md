# 倉庫番 (qgb_soukoban) 設計書

- 版: v0.1 (原案 / Codex セカンドオピニオン前)
- 作成: 2026-07-11
- 関連: [test-design.md](test-design.md) / [qgb-design.md](qgb-design.md)

## 1. 目的と要件

ブラウザで動作するテキストアートグラフィックの倉庫番ゲームを TDD で開発する。品質保証は qgb (quality-gate-builder) の機械ゲートで担保する。

### 機能要件

| ID | 要件 |
|---|---|
| F-01 | 倉庫番の標準ルール(移動・箱押し・全箱ゴールで勝利)で遊べる |
| F-02 | 手作り 10 ステージ(チュートリアル→高難度の難易度カーブ) |
| F-03 | ランダム生成モード(生成された面もクリア可能性を保証) |
| F-04 | undo(多段。1 手ずつ巻き戻し)とリセット |
| F-05 | ステージ選択メニュー + クリア記録の永続化 (localStorage) |
| F-06 | 歩数カウント + そのステージの最短手数の表示 |
| F-07 | クリア時のリプレイ記録と再生 |
| F-08 | テキストアートグラフィック(等幅文字ベース描画 + CSS カラー) |

### 非機能要件

| ID | 要件 |
|---|---|
| NF-01 | vanilla HTML/CSS/JS。ビルド工程なし、npm 依存ゼロ |
| NF-02 | コアロジックは DOM 非依存の純粋 ESM とし、node:test (Node 22 組込) で単体テスト可能 |
| NF-03 | 全ステージ(手作り + 生成)のクリア可能性を機械検証(ソルバー)で担保 |
| NF-04 | qgb の品質ゲートに接続し、判定は機械証跡 (gate.json) で説明可能 |

### クリア可能性担保の方式(F-02/F-03/NF-03 の実現)

- **手作りステージ**: BFS ソルバーで全 10 面の可解性を機械検証。最短手数はソルバー出力をステージデータに焼き込み、テストで「焼き込み値 == ソルバー再計算値」を照合する(手書き値の混入を防ぐ。記録の真正性)。
- **生成ステージ**: ゴール状態から逆押し(pull)で構成的に生成するため、構成上必ず可解。加えてプロパティテスト(固定シード群 × 全難易度)でソルバーによる全数可解確認を行う(二重担保)。

## 2. 技術選定と制約

| 項目 | 選定 | 理由 |
|---|---|---|
| 実装言語 | vanilla JS (ES2022, ESM) | ユーザー選択。依存ゼロで審美的な UI を自作 |
| テスト | node:test + node:assert (Node 22 組込) | npm 依存を増やさない。`node --test` のみで完結 |
| 実行方法 | ローカル HTTP サーバ経由 | ESM は file:// で CORS 制限により動かない。`serve.ps1`(または `py -3 -m http.server`)を同梱 |
| ソルバー | 状態空間 BFS(移動単位)+ デッドロック枝刈り | 10 面規模(箱 ≤ 6、盤面 ≤ 12×10 目安)では BFS で十分。最短「歩数」が直接得られる |
| 生成器 | 逆押し生成 + シード付き PRNG (mulberry32) | 可解性の構成的保証。シード固定で決定論 → テスト可能 |
| UI 検証 | コアと UI の分離 + 構文検査 + 目視 | jsdom 等のテスト専用依存を増やさない(方針)。ロジックはすべてコア側に置く |

## 3. モジュール構成

```
index.html            # エントリ (script type="module")
styles.css            # 配色・レイアウト (テキストアートの装飾)
serve.ps1             # ローカルサーバ起動 (Windows)
src/
  core/               # ★ DOM 非依存・純粋 ESM (node:test の対象)
    board.js          # 盤面モデル: テキスト形式のパース/シリアライズ/検証
    game.js           # ゲーム状態機械: 移動・押し・undo・リセット・勝利判定・歩数・リプレイログ
    solver.js         # BFS ソルバー: 可解性判定 + 最短歩数 + 解手順
    generator.js      # 逆押しステージ生成器 (シード付き)
    rng.js            # mulberry32 PRNG
    stages.js         # 手作り 10 ステージデータ (テキストアート + メタ)
  ui/                 # DOM 依存層 (薄く保つ。ロジックを書かない)
    render.js         # 盤面 → DOM (文字 span + CSS クラス)
    storage.js        # localStorage の読み書き (スキーマ v1)
    app.js            # 画面遷移・キー入力・メニュー・リプレイ UI
tests/                # node:test (*.test.mjs)
tools/
  verify-stages.mjs   # 全ステージ可解性検証 CLI (qgb ゲート用、exit code + 証跡表出力)
docs/                 # 本設計文書群
.quality-system/      # qgb (別文書)
```

依存方向: `ui → core` の一方向のみ。`core` は `document`/`window` を参照しない。

## 4. 盤面テキスト形式

標準 Sokoban 記法を採用(コミュニティ互換):

| 文字 | 意味 |
|---|---|
| `#` | 壁 |
| ` ` (空白) | 床 |
| `@` | プレイヤー |
| `+` | プレイヤー (ゴール上) |
| `$` | 箱 |
| `*` | 箱 (ゴール上) |
| `.` | ゴール |

検証規則 (`board.js` の `validate()`):

1. プレイヤーがちょうど 1 人
2. 箱の数 == ゴールの数、かつ 1 個以上
3. 全ての箱・ゴール・プレイヤーが壁で囲まれた領域内にある(外周流出なし; flood fill で検査)
4. 使用可能文字のみで構成される
5. 既に全箱がゴール上(= 開始即クリア)の面は不正とする

## 5. コアロジック仕様 (game.js)

- **移動**: 上下左右 1 マス。移動先が壁なら不発(状態不変・歩数不変)。移動先が箱なら、箱のさらに先が床/ゴールのときのみ押して移動(箱 2 連続・壁は押せない)。
- **歩数 (moves)**: プレイヤーが実際に移動したら +1(押しも 1 歩)。不発は数えない。
- **undo**: 直前の 1 歩を巻き戻す(箱位置・プレイヤー位置・歩数・リプレイログすべて)。多段可。初期状態より前には戻れない。
- **リセット**: 初期状態に完全復帰。
- **勝利判定**: 全箱がゴール上。勝利後の入力は無視。
- **リプレイログ**: 有効だった移動を `U/D/L/R` の文字列で記録。undo はログ末尾を除去(= ログは常に「初期状態から現在状態への再現手順」)。

## 6. ソルバー仕様 (solver.js)

- 状態: `(プレイヤー位置, 箱位置集合)`。初期盤面から BFS(移動単位)。
- 返り値: `{ solvable: bool, minMoves: number|null, solution: "UDLR..."|null, stats }`
- 枝刈り:
  - 単純デッドロック: ゴール上でない箱が凹角(直交 2 方向が壁)に入った状態は展開しない
  - 訪問済み状態集合 (文字列キー化)
- 資源上限: 展開状態数上限 (既定 1,000,000) / 超過時は `{ solvable: null, reason: "limit" }` を返し、例外にしない(担保対象ステージは上限内で解けることをテストで保証)。

## 7. 生成器仕様 (generator.js)

- 入力: `{ seed, width, height, boxCount, pullSteps }`(難易度プリセット: easy/normal/hard がこれらを決める)
- 手順:
  1. 外周壁 + ランダム内壁の部屋を生成(床連結性を flood fill で保証)
  2. ゴール位置に箱を置いた「解けた状態」を作る
  3. プレイヤーがランダムに `pullSteps` 回、箱を「引く」(pull は push の逆操作なので、逆再生すれば必ず解ける)
  4. 最終プレイヤー位置・箱位置を初期状態として出力
- 棄却条件(満たすまで再試行、シードから決定論的に派生): ソルバーの `minMoves` が難易度別下限未満 / 箱が 1 個も動いていない / validate() 不合格
- 同一シード + 同一パラメータ → 同一ステージ(決定論)。

## 8. UI 仕様

### 画面

1. **タイトル/ステージ選択**: 10 ステージのカード(クリア済みマーク・自己ベスト歩数)+ ランダムモードカード(難易度選択)
2. **ゲーム画面**: 盤面(テキストアート)、HUD(ステージ名 / 歩数 / 最短手数 / 自己ベスト)、操作ガイド
3. **クリアオーバーレイ**: 歩数 vs 最短手数、リプレイ再生ボタン、次のステージ / メニューへ

### キー操作

| キー | 動作 |
|---|---|
| ↑↓←→ / WASD | 移動 |
| Z / Backspace | undo |
| R | リセット |
| Esc | メニューへ戻る |

### 表示・配色

- 等幅フォント。1 セル = 1 文字 span、種別ごとに CSS クラス(壁/床/ゴール/箱/箱onゴール/プレイヤー)で彩色。
- ダーク基調のモダンな配色(詳細は実装時に frontend-design の指針で決定)。CSS のみで装飾し文字グリッドは崩さない。

### localStorage スキーマ (storage.js)

```json
{
  "version": 1,
  "stages": {
    "<stageId>": { "cleared": true, "bestMoves": 42, "replay": "UDLR...", "clearedAt": "ISO8601" }
  }
}
```

キー名: `qgb-soukoban/v1`。パース失敗・版不一致時は初期化(破壊しない: 旧キーは残す)。

## 9. リプレイ形式

- 記録: `U/D/L/R` の列(§5 リプレイログ)。クリア時に localStorage へ保存。
- 再生: 初期盤面からログを 1 手ずつ適用(タイマー駆動、等速/倍速)。再生ロジックは core の `game.js` を UI から呼ぶだけ(専用実装を持たない)。
- 検証: リプレイ文字列を適用して勝利状態に到達することをテストで保証(ソルバーの解もリプレイ形式で表現され、同一の適用関数を通る)。

## 10. 開発体制

- 設計/テスト設計/qgb 設計: Fable 5 原案 → Codex CLI セカンドオピニオン (read-only)
- 実装: Sonnet サブエージェントに委任、TDD (Red→Green→Refactor)
- レビュー: Codex CLI (read-only) で Major/Critical 収束まで
- 品質ゲート: qgb (詳細は [qgb-design.md](qgb-design.md))
- マイルストーンごとに git commit/push で履歴を固定(qgb evidence の保存もコミットで行う)
